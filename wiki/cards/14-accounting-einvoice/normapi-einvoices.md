# NormAPI – German e-invoices (XRechnung, ZUGFeRD) (коннектор)

## Суть
В сессии коннектор NormAPI подключён [1].
По инструкциям сервера, NormAPI проверяет, разбирает и создаёт немецкие электронные счета XRechnung и ZUGFeRD по набору правил KoSIT и указывает версию набора в каждом результате [3].
Описание в каталоге отсутствует, поэтому сведения взяты из инструкций сервера [1][3].

## Для чего
По списку инструментов и инструкциям сервера: проверка счёта, разбор полученного счёта, создание счёта и объяснение кодов правил [2][3].
нет данных о том, кто пользуется коннектором; в инструкциях описаны профили для госзаказчика и для бизнеса [3].

## Возможности
- `validate_invoice` проверяет счёт; вердикт — `acceptable`; у каждого нарушения бизнес-правила есть пояснение: что значит, почему и как исправить [3].
- `parse_invoice` читает полученный счёт в данные, перечисляет нераспознанные значения в `notMapped` и не требует учётной записи [3].
- `generate_invoice` создаёт счёт, который проходит проверку до возврата; требует учётной записи NormAPI и расходует месячный лимит [3].
- `explain_rule` объясняет код правила, например BR-DE-15, который пользователь уже имеет [3].
- Профиль выбирается по получателю: xrechnung по умолчанию для госзаказчика, en16931 для бизнеса без Leitweg-ID, контактного лица и электронных адресов [3].
- Поддерживаются XRechnung в UBL или CII и ZUGFeRD/Factur-X PDF [3].
- Если в аккаунте загружен фирменный бланк, PDF в формате ZUGFeRD печатается на нём автоматически [3].

## Чем выделяется
- Мнение: проверка и разбор не требуют учётной записи, что удобно для первичного контроля счетов.
- Сервер сообщает версию набора правил KoSIT в каждом результате [3].
- Инструкции сервера говорят, что это техническая проверка, а не налоговая или юридическая консультация [3].

## Ограничения и риски
- Для создания счёта нужна учётная запись NormAPI, и каждый созданный счёт расходует месячный лимит [3].
- Счета обрабатываются сервисом в памяти и, по инструкциям, не сохраняются [3].
- Класс данных B выбран потому, что счета как документы обрабатывает сервис [3].
- Цена и тарифы в выдержках не указаны, упомянут только месячный лимит объёма [3].
- Описание в каталоге отсутствует, сведения взяты из инструкций сервера [1][3].
- нет данных о месте обработки данных и о сроках хранения журналов.

## Когда не подходит
- Мнение: налоговые решения, например по ставкам НДС, инструмент не заменяет: по инструкциям это техническая проверка, а не налоговая консультация [3].
- Мнение: если счёт нужно создать без учётной записи, `generate_invoice` для этого не подходит [3].
- Мнение: счета для получателей вне Германии выходят за описание коннектора, которое говорит о немецких счетах [1][3].
