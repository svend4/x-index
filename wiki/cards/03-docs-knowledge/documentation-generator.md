# documentation-generator

## Суть
Скилл автоматизирует создание документации: API-документация, README, changelog, документация кода и проекта, страницы wiki [2].
Состояние в инвентаре — `enabled` [1].
В примере выдержки функция собирает текст README из названия проекта, описания и разделов [2].

## Для чего
- Создание README для проекта по названию, описанию и разделам [2].
- API-документация, changelog и страницы wiki [1][2].
- Документация кода и документация проекта [2].
- нет данных о том, для каких команд или проектов предназначен скилл.

## Возможности
- Сценарии по описанию: генерация API-документации, README, changelog, страниц wiki, документации кода и проекта [2].
- Функция `generate_readme` формирует текст README с разделами Installation, Quick Start, Features и Usage [2].
- нет данных о поддерживаемых языках программирования и форматах вывода.

## Чем выделяется
- Мнение: шаблон README в примере задаёт каркас для первого черновика, который затем правит человек.
- Мнение: объединение API-документации, README и changelog в одном скилле упрощает поддержку документации проекта.

## Ограничения и риски
- В примере текст по умолчанию для раздела Usage — заглушка, поэтому результат нужно проверять перед публикацией [2].
- Выдержка не описывает, как проверяется соответствие сгенерированного текста коду [2].
- Сценарии документации кода и проекта предполагают чтение исходного кода; что именно читается и куда пишется, в выдержке не указано [2].
- Класс данных C: скилл создаёт файлы README и changelog в проекте [2].
- нет данных о цене, способе подключения и месте обработки данных.
- Описание и пример на английском; языки интерфейса в выдержках не указаны [2].

## Когда не подходит
- Мнение: если нужна документация с фактами о продукте или процессе, которых нет в коде, шаблон не заменит автора.
- Мнение: для юридических и регламентных документов с точным текстом шаблон генератора не подходит.
