# vault-anything (плагин: Obsidian-вики по коду и документам)

## Суть
Плагин строит вики в формате Obsidian из исходного кода проекта и статических файлов в папке `raw/`. Каждая страница задумана как самодостаточная: её можно читать как документацию и как контекст для модели. Скиллы `vault` и `vault-update` запускают конвейер, агенты делают сбор и запись.

## Для чего
- Документация проекта, которую нужно поддерживать вместе с кодом.
- Вики из статических документов в `raw/` (выгрузки, спецификации, отчёты).
- Обновление только изменённых частей через `vault-update`.

## Возможности
По `vault/SKILL.md` (прочитан 2026-11-10):
- Аргументы: каталог проекта, `--workspace` (по умолчанию `<проект>/vault-anything/`), `--lang` (по умолчанию en).
- Фаза 1: сканирование файлов скриптом, определение фреймворков и точек входа, пакеты для агентов.
- Фаза 2: агенты `file-analyzer` по пакетам файлов, до 5 одновременно.
- Фаза 3: кластеризация понятий и скелет вики.
- Фаза 4: агенты `page-writer` по категориям, каждая страница пишется прозой со ссылками wikilinks (в двойных квадратных скобках).
- Фаза 5: проверка качества скриптом, итоговая оценка из 100.
- Рекомендация: коммитить вики и слой `raw/` вместе с кодом, исключая файл отчёта проверки.

## Чем выделяется
- Мнение: это готовая реализация той же идеи, что описана в схеме этой вики: сырой слой, агенты-писатели, проверка скриптом. Для кода это удобнее, чем писать конвейер с нуля.
- Мнение: проверка качества встроена в конвейер и не зависит от агентов.

## Ограничения и риски
- Заточен под исходный код. Для каталога инструментов (тысячи записей без кода) подходит хуже, чем конвейер этой вики.
- Требует Node.js и `jq` в окружении. Без них скрипты не запустятся (указано в SKILL.md).
- Класс B: содержимое файлов проекта уходит модели. Не подключать к закрытым репозиториям без правила владельца.

## Когда не подходит
- Большие каталоги без кода и с нестабильной структурой.
- Проекты, в которых нельзя передавать содержимое модели.
