# session-status-sweep

## Суть
Скилл собирает статус нескольких параллельных сессий Claude Code (код, концепцию и документацию) в режиме только чтения и сводит его в один реестр [1][2].
Статус опирается на данные (коммиты, ветки, файлы), а не на самоописание сессий [2].
В сессиях ничего не меняется [2].

## Для чего
- Общий статус проектов, когда параллельных сессий много [2].
- Реестр статусов: проект, сессия, ветка, последний коммит, влит ли он в main, код, концепция, документация, блокер и что нужно от владельца [2].
- нет данных о том, для кого предназначен реестр, сверх описания.
- Группа инвентаря: «аудит и качество» [1].

## Возможности
- Инвентаризация сессий без сообщений в них: список, повторы по названию, статус (выполняется, ждёт ответа, неактивна, не в сети) [2].
- Для каждой сессии называется ветка и отдельно проверяется, что именно влито в main [2].
- За один раз не больше пяти сессий; приоритет у сессий, которые ждут решения владельца [2].
- Пилот на одной сессии, оценка ответа по критериям, затем остальные [2].
- Шаблон запроса к сессии: только чтение, git status и git log, ответ по пунктам — реализация, технология, концепция, документация, блокеры и изменения с прошлой проверки [2].
- Критерии хорошего ответа: названа ветка, есть коммиты и файлы, нет предложений что-то изменить без запроса, непроверенное помечено [2].
- Пересборка реестра не чаще раза в неделю [2].

## Чем выделяется
- Мнение: опора на коммиты и ветки, а не на ответы сессий, делает статус проверяемым.
- Мнение: требование помечать непроверенное снижает риск выдать предположение за факт.

## Ограничения и риски
- Сессии в статусе «выполняется» не трогаются, пока ход не закончится [2].
- Если в сессиях есть отчёты о найденных секретах или ключах, сначала подтверждается, что ключи отозваны [2].
- Непроверенное в ответе сессии должно помечаться как непроверенное; без этого ответ не считается хорошим [2].
- нет данных о лимитах параллельных сессий, цене и хранении данных сессий.

## Когда не подходит
- Мнение: при одной-двух сессиях реестр избыточен: достаточно разового запроса по шаблону [2].
- Мнение: если нужен аудит кода, тестов и документации по объектам, а не статус сессий, подходит [[session-audit-waves]].

## Альтернативы
- [[session-audit-waves]] — массовый аудит кода, тестов и документации по объектам.
- [[audit-question-bank]] — банк вопросов для аудита; не сводит статусы сессий.
