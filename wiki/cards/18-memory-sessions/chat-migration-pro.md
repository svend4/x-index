# chat-migration-pro

## Суть
Скилл PRO версии 2.0 для продолжения долгих проектов между чатами; по описанию создаёт checkpoint-файлы и BRIDGE-документ, проверяет их, а шаг Git commit опционален [1][2].
По описанию это расширенная версия базового варианта: автоматизация и метрики [2].

## Для чего
- Сценарии по описанию: контекст больше 180 тысяч токенов, проект на три и более чатов, нужна автоматизация checkpoint, версионирование и метрики, работа в команде [2].
- Адресат по описанию: пользователь долгого проекта, в том числе работающий в команде [2].
- нет данных о подтверждённых результатах применения; число примеров из практики заявлено автором [2].
- Группа инвентаря: handoff и чекпоинты [1].

## Возможности
- Режимы: базовый (ручной), авто (автоматический) и enterprise с Git и метриками [2].
- Автоматический checkpoint по описанию: анализ чата, создание файлов, валидация, BRIDGE-документ и опциональный Git commit [2].
- По описанию автора: система валидации с 50+ проверками [2].
- По описанию автора: шаблоны для 8 типов проектов, Python-скрипты для автоматизации, интеграция с Git, metrics dashboard [2].
- Заявленное время: около 3 минут в авто-режиме против 10–15 минут в ручном [2].
- нет данных о формате метрик и о месте хранения файлов.

## Чем выделяется
- Мнение: сочетание автоматической проверки и Git-интеграции отличает PRO от базовой версии; это мнение по описанию [2].
- Мнение: заявленные 30+ примеров из практики по выдержкам проверить нельзя.

## Ограничения и риски
- В сессии скилл включён [1].
- Шаг Git commit, по описанию опциональный, записывает изменения в репозиторий владельца, поэтому класс данных C [2].
- Создаются файлы checkpoint и BRIDGE-документ; где они сохраняются, в выдержке не указано [2].
- Время работы и число примеров из практики заявлены автором и по выдержкам не проверены [2].
- нет данных о цене, модели оплаты, способе подключения и месте обработки данных.

## Когда не подходит
- Мнение: если проект укладывается в один чат и контекст далеко от лимита, автоматизация избыточна.
- Мнение: если менять репозиторий нельзя, шаг Git commit не используйте; по описанию он опционален [2].
